# http2socks

Небольшой прокси-конвертер: принимает HTTP proxy-соединения локально и отправляет трафик через SOCKS5-сервер. 

Программа кроссплатформенная и работает как под Linux, так и под Windows.

Поддерживает:
- обычные HTTP-запросы (например, `GET http://example.com/...`);
- метод `CONNECT` для туннелирования (обычно используется для HTTPS через HTTP-прокси).

## Как это работает

1. Программа слушает TCP-адрес локального HTTP-прокси.
2. При новом клиентском подключении парсит первую строку HTTP-запроса и заголовки.
3. Определяет целевой хост/порт.
4. Определяет, идти через SOCKS5 или подключаться напрямую (по спискам `-bypass`/`-proxied`), и устанавливает соединение.
5. Выполняет SOCKS5 handshake без аутентификации (`NO AUTH`).
6. Отправляет SOCKS5 `CONNECT` к целевому хосту и начинает двустороннюю прокачку данных.

## Параметры запуска

- `-listen` — адрес и порт, на котором поднимается локальный HTTP-прокси.  
  Значение по умолчанию: `127.0.0.1:8080`
- `-socks` — адрес и порт SOCKS5-прокси, через который идет исходящий трафик.  
  Значение по умолчанию: `127.0.0.1:1080`
- `-bypass` — список хостов через запятую, к которым подключаться напрямую, минуя SOCKS5-прокси.  
  Значение по умолчанию пустое (весь трафик идёт через SOCKS5).
- `-proxied` — список хостов через запятую, которые направлять через SOCKS5-прокси; все остальные хосты подключаются напрямую.  
  Значение по умолчанию пустое (весь трафик идёт через SOCKS5).

`-bypass` и `-proxied` взаимоисключающие: используйте только один из них.

### Сопоставление хостов

Шаблоны хостов регистронезависимы. Шаблон может начинаться с `*.`:

- `example.com` совпадает с `example.com` и всеми его поддоменами (`www.example.com`, `api.example.com`);
- `*.example.com` совпадает с `example.com` и его поддоменами.

### Примеры

```bash
# Через SOCKS5 идёт только example.com, остальное — напрямую
./http2socks -socks 127.0.0.1:1080 -proxied "example.com,*.internal.org"

# Всё идёт через SOCKS5, кроме локальных хостов
./http2socks -socks 127.0.0.1:1080 -bypass "localhost,*.lan"
```

## Запуск

### Через `go run`

```bash
# for Linux
go run main.go -listen 127.0.0.1:8080 -socks 127.0.0.1:1080

# for Windows
GOOS=windows GOARCH=amd64 go run main.go -listen 127.0.0.1:8080 -socks 127.0.0.1:1080
```

### Сборка и запуск бинарника

```bash
# for Linux
go build -o http2socks main.go
./http2socks -listen 127.0.0.1:8080 -socks 127.0.0.1:1080

# for Windows
GOOS=windows GOARCH=amd64 go build -o http2socks.exe main.go
./http2socks.exe -listen 127.0.0.1:8080 -socks 127.0.0.1:1080
```

После запуска программа выводит:
- адрес локального HTTP-прокси (`HTTP is listening: ...`);
- адрес SOCKS5-сервера (`SOCKS5 server: ...`);
- списки хостов bypass/proxied, если они заданы (`Bypass list: ...` / `Proxied list: ...`).

## Пример использования

Пример запроса через локальный HTTP-прокси:

```bash
curl -x http://127.0.0.1:8080 http://example.com
```

## Ограничения

- SOCKS5-аутентификация не поддерживается (только `NO AUTH`);
- порт по умолчанию выбирается по схеме: `80` для `http`, `443` для `https`/`wss` и метода `CONNECT`.
